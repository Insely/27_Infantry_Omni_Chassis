# 迁移说明

日期：2026-10-05。原始步兵来源为 `Infantry/27_Infantry/27_Infantry_{Gimbal,Chassis}`；参考架构为 `27_fold/27_Fold_{Gimbal,Chassis}`。工作区旧记录中的 `27_infantry_All` 路径不存在，使用磁盘现存的双板步兵版本。输入源码没有修改。

## 分工与数据流

- Gimbal：DT7/FSI6X/VT13 解码、遥控/键鼠解释、自瞄目标、Pitch 控制、Yaw PID/底盘扰动补偿、摩擦轮控制。
- Chassis：全向轮运动/力矩正逆解、斜坡、轮速 PID、电流限幅、Yaw MIT 速度指令执行、拨弹速度/位置环、单发及卡弹回退、BMI088、裁判系统、UI、超电。
- 云台通过 BoardLink 发送车体目标速度、Yaw 电机目标角速度和模式，底盘不再解释遥控器原始通道/键鼠。
- 底盘回传 Yaw 编码器角度/速度、底盘陀螺仪 Z 角速度以及裁判射击信息。Yaw 的底盘扰动补偿保持原公式，只把其数据来源改成反馈帧。
- BoardLink 不包含 `Global_status` 或执行器控制逻辑；`app_api.c` 负责协议与应用状态转换。枚举用显式映射，不能直接把应用枚举强转后发给另一块板。
- 配置和协议分别位于各板标准目录；两块板独立编译，通信与公共硬件参数需要同步维护。

控制任务每 1 ms 顺序执行接收状态转换、控制解算、电机发送和通信发送，遥控解释每 2 ms 执行一次，保留原遥控输入积分周期。裁判/UI 和看门狗分别运行独立任务，避免 UI 发送阻塞控制环。TIM13 保留 1 kHz IMU 更新/请求；视觉遥测保留 TIM14 原来的触发方式。

## 驱动与通信变化

- 引入 fold 的 DJI/DM/LZ 电机库和 DM/HI12/HI14/Hipnuc/XRobot IMU 文件；当前车仍使用 DM 外置 IMU + Chassis 板载 BMI088。其他驱动作为库提供，没有切换当前传感器。
- DM MASTER_ID 基址独立为 `DM_FEEDBACK_ID_BASE=0x01`，保留旧车硬件设置。fold 的 0x11 基址没有直接覆盖过来。反馈增加时间戳，用于识别真实 Yaw 反馈是否过期。
- 底盘/云台应用对新 DM 驱动的原始 MIT 位置做归一化，保持旧算法的弧度坐标约定。
- CAN 接收排空 FIFO，检查标准帧、数据帧、DLC，再分发给协议或驱动；修复原 DJI 接收上界越界；CAN 发送正确处理长度。
- UART DMA 收发句柄分开，完成/错误回调释放 BoardLink 缓冲区，USART2/3 也支持错误恢复。串行消息支持 CRC、任意分段、粘包和坏帧后的重同步。
- RS485 使用云台发起请求、底盘收到完整请求后应答，避免底盘无请求持续发送。发起失败不会提前耗尽快速重发计数。
- XY、Yaw/旋转指令、控制模式、发射模式分别计时，任一超过 20 ms 即失效，不能用某一类持续收到的帧替代其他类的新鲜度。锁定时底盘仍发零电流，拨弹与摩擦轮停止输出。
- 自瞄保持原 SP 布局、目标跳变过滤、前馈增益；入口统一校验长度/CRC，防止原 `memcpy(len)` 越界。普通 UART 板间模式下视觉使用 USB；默认 CAN/RS485 模式仍使用 UART1。
- 补上 Chassis 板载 IMU 的初始化调用。原工程定义了 `IMU_Init` 却未调用，本版在控制初始化中调用后才允许周期更新。

## 保持的控制策略及有限修正

全向轮解算、PID、前馈、斜坡、归一化电流限幅、Yaw 原 PID 和扰动补偿系数不重调。原 Chassis 功率限制调用和拨弹热量限制处于注释状态，本版保持现状，没有擅自启用；现有功率/裁判代码仍保留。

迁移时修正了几个直接可见的错误，需与正常架构变更一起上机确认：

1. 旧 Pitch 自瞄直接读 `DM_Motor_data[0][1]`，与本车 `PITCHMotor=DM_CAN_1_1` 不一致；改为通过实际 Pitch 电机接口读反馈。控制公式及前馈参数保留。
2. 退弹分支原来给 `trigger_mode` 赋 `DEBUG_SHOOT`，数值实际落在 `SINGLE`；改为对应的 `DEBUG_TRIGGER`。
3. 摩擦轮调试数组只有 2 个 float，却发送 3 个；改为发送 2 个，避免越界读取。
4. 新 HI14 库里的 32 位拼接移位 32 改为无符号移位 24；DM disable 使用电机所属 CAN，不固定 CAN1；Hipnuc 输出函数初始化局部变量。
5. 视觉在线计数在统一控制周期中只递减一次，避免合并 Pitch/Yaw 计算后变成双倍递减。

旧 Pitch 开机纠偏行为（连续到位计数 / 最多约 3 秒、纠偏阶段独立输出）保留；不要把软件回放通过当作已验证上电机械动作。

## 使用与验证边界

`ROBOT_SENTRY` 只是明确的预留角色：应用不初始化和发送步兵电机命令，协议继续工作。不是可直接运行的哨兵软件。

两块板需使用匹配的固件。第一轮实车验证应确认原接线、反馈 ID、轮子方向、Pitch/Yaw 方向与零点、模式切换、断开板间链路时的输出、发射单发/连发/退弹、自瞄与 UI。RS485/UART 接线需要按所选端口变更。

已提供可复现的软件验证；没有烧录或执行实车试验，也没有测量实际任务抖动、CAN 总线占用及机械控制效果。编译日志保留了上游宏重复定义、未使用变量、预编译 AHRS 库 wchar_t 和链接脚本 RWX 警告，没有声称零警告。
